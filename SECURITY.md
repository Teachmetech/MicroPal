# Security policy

MicroPal is an early development project. Security fixes target the latest production branch and latest public release. There is no long-term support commitment for older versions.

## Reporting a vulnerability

Report vulnerabilities privately through [GitHub Security Advisories](https://github.com/Teachmetech/MicroPal/security/advisories/new). If that route is unavailable, use an existing private contact method on [the maintainer's GitHub profile](https://github.com/Teachmetech). Do not disclose exploit details or sensitive device data in a public issue. This project does not promise a fixed response deadline.

Include the affected version, reproduction steps, impact, and a minimal example if safe. Remove credentials, personal paths, USB serial numbers, and proprietary firmware/source. Coordinate public disclosure with the maintainers where possible.

## Trust boundaries

- Device operations are disabled in untrusted workspaces. Running a file executes Python on the selected board. Board code and imported modules can affect connected equipment and use whatever network capabilities their firmware provides.
- `pythonPath`, `mpremotePath`, and `esptoolPath` are machine/User-scoped executable settings, never shell commands. Executables run with the user's local privileges. An empty `pythonPath` detects Python; empty tool paths use managed executables. A nonempty tool path takes precedence over its managed executable. Only select installations you trust.
- **Set Up Tools** and **Repair Tools** explicitly create a private Python virtual environment and download `mpremote==1.29.0`, `esptool==5.0.2`, and their dependencies from official PyPI. Python 3.10+ with `venv`/`ensurepip` is a user prerequisite; no Python runtime is bundled. Installation can execute package build/install code locally. MicroPal does not modify global Python packages or system `PATH`, and never installs or downloads packages merely on activation.
- Managed environments live under the extension's global storage `tools/` directory. Each `env-UUID` generation stays at its original path. An atomically written `tools.json` pointer selects it only after verification. Failure/cancellation preserves the previously active generation, and earlier successful generations remain on disk. Setup/repair first disconnect MicroPal device operations and wait for local serial owners to close.
- Commands use an executable plus argument array with no shell interpolation. Interactive REPL uses a real editor terminal with the executable and arguments specified directly.
- Serial ownership is serialized within one extension instance. Another application or editor window can still interfere. Discovery enumerates ports; USB metadata is not device authentication.
- After an explicit Connect fails to open the selected port, macOS/Linux recovery inspects its owners using `lsof` and `ps`. Known MicroPal-managed REPL workers owned by the current user can receive SIGTERM automatically; disable `microPal.autoReleasePort` to require confirmation. Other processes always require **Release Port and Connect**, and SIGKILL requires a separate **Force Release and Connect** confirmation. Each signal rechecks PID, user, start time, full command, and selected-port ownership. Recovery never signals parents, process groups, another user, or a newly discovered owner. Only display names and PIDs appear in the UI/log. Process inspection cannot provide an atomic identity check and signal; another local process running as the same user remains within the local trust boundary.
- Reconnect uses a stable USB serial number when available, otherwise the exact path. A path can be reassigned to another device. No command is replayed automatically.
- Native **ESP32 Files** access is writable: editor Save, rename, delete, and transfers modify the selected board. Deletes have no desktop recycle bin. Native Explorer drag moves the source; Option-drag on macOS, Ctrl-drag on Windows/Linux, or copy/paste keeps it. Project-sync exclusions do not apply to items selected for native transfers.
- Device URIs contain an explicit connection session. Workspace trust, URI confinement, and the expected session are checked before filesystem work; old dirty documents cannot save onto a newly connected board. Explicit reconnects invalidate old documents. Save unsaved changes locally before closing a stale device editor.
- A mount descriptor containing the session and selected USB port metadata is stored in extension global state before a workspace-root change. Host-restart restoration requires a matching stable USB serial identity and uses port enumeration without a REPL probe; it is unavailable for ports without that identity. These records contain local USB metadata, not authentication credentials. Explorer can subsequently request filesystem data through raw REPL.
- Filesystem operations refuse an active MicroPal Run/REPL owner. When idle, raw-REPL access can still interrupt code started by `boot.py`, `main.py`, or another client. Filesystem watches never poll the board; explicit Refresh or native Explorer/editor requests perform reads.
- Direct filesystem writes use a hidden staging file before `os.rename`. Failed transfers preserve the destination but can leave staging data on the board; remove it deliberately after reconnecting. If the device filesystem cannot replace an existing destination with `os.rename`, overwriting fails without deleting the original. Multi-file copies/moves are not transactional; interruption can leave partial destinations and, for moves, some successfully copied source items removed.
- Firmware flashing requires explicit chip, image, address, erase mode, and confirmation. It stops prior serial owners and disables reconnect until you explicitly Connect again. Written sectors are replaced; full erase deletes all device files. esptool validates image/chip compatibility; the extension never uses its force option.
- Sync copies selected files and overwrites matching paths. Default exclusions reduce accidental uploads but cannot identify all secrets. Symlinks are skipped; remote files are never deleted by sync.
- Subprocesses have bounded captured output and command deadlines, except an explicitly running script. Cancellation waits for local process closure before allowing a new owner.

The extension has no telemetry, network service, or automatic firmware downloader. Its managed dependency installer uses network access only for explicitly requested setup/repair; activation and ordinary device operations do not trigger package downloads. Users can instead supply external tool executables. These claims apply to this extension's behavior, not arbitrary board code, editor behavior, package build scripts, or selected executables.
